## Overview

`sherpa-onnx` is a high-performance, cross-platform text-to-speech (and speech-to-text) framework that uses **ONNX Runtime** for inference. It is designed to be self-contained and highly portable, making it an ideal replacement for the `pocket-tts` (Candle-based) engine.

### Key Benefits
- **Portability:** Supports Windows, macOS, Linux, Android, iOS, and WebAssembly.
- **Efficiency:** Uses prebuilt C++ ONNX Runtime binaries with thin Rust FFI wrappers.
- **Model Variety:** Supports multiple TTS architectures including VITS, Piper, Kokoro, Matcha, and KittenTTS.
- **Low Overhead:** Significantly fewer transitive dependencies compared to the previous Candle-based stack.

## Rust API Usage

The following is the core API pattern for using `sherpa-onnx` in Rust, based on the official examples.

### 1. Configuration (`OfflineTtsConfig`)

To initialize the TTS engine, you must provide paths to the ONNX model files and configuration JSONs.

```rust
use sherpa_onnx::{OfflineTts, OfflineTtsConfig, OfflineTtsPocketModelConfig, OfflineTtsModelConfig};

let config = OfflineTtsConfig {
    model: OfflineTtsModelConfig {
        pocket: OfflineTtsPocketModelConfig {
            lm_flow: Some("models/lm_flow.int8.onnx".into()),
            lm_main: Some("models/lm_main.int8.onnx".into()),
            encoder: Some("models/encoder.onnx".into()),
            decoder: Some("models/decoder.int8.onnx".into()),
            text_conditioner: Some("models/text_conditioner.onnx".into()),
            vocab_json: Some("models/vocab.json".into()),
            token_scores_json: Some("models/token_scores.json".into()),
            voice_embedding_cache_capacity: 50,
        },
        num_threads: 2,
        debug: false,
        ..Default::default()
    },
    ..Default::default()
};

let tts = OfflineTts::create(&config).expect("Failed to create OfflineTts");
```

### 2. Generation Configuration (`GenerationConfig`)

This struct controls the speed, voice cloning, and other generation parameters.

```rust
use sherpa_onnx::{GenerationConfig, Wave};
use std::collections::HashMap;

// For zero-shot voice cloning, read a reference WAV file
let wave = Wave::read("voices/reference.wav").expect("Failed to read reference");

let mut extra = HashMap::new();
extra.insert("max_reference_audio_len".to_string(), serde_json::json!(10.0));
extra.insert("seed".to_string(), serde_json::json!(42));

let gen_config = GenerationConfig {
    speed: 1.0,
    reference_audio: Some(wave.samples().to_vec()),
    reference_sample_rate: wave.sample_rate(),
    extra: Some(extra),
    ..Default::default()
};
```

### 3. Speech Generation

Speech is generated by passing text and the generation config. A progress callback can optionally be provided.

```rust
let audio = tts.generate_with_config(
    "Hello, world!",
    &gen_config,
    Some(|samples: &[f32], progress: f32| -> bool {
        println!("Progress: {:.1}%", progress * 100.0);
        true // Return true to continue, false to stop
    }),
).expect("Generation failed");

// Save to file
audio.save("output.wav");
```

## PDF Documentation Summary (sherpa.pdf)

The [sherpa.pdf](https://github.com/k2-fsa/sherpa/releases/download/doc/sherpa.pdf) provides a comprehensive overview of the entire Sherpa ecosystem. Key takeaways include:

1.  **Project Goal:** Deployment of "Next-gen Kaldi" models. It focuses strictly on inference and deployment, not training.
2.  **Architecture:**
    *   **Sherpa (original):** Uses PyTorch for inference.
    *   **Sherpa-ONNX:** Uses ONNX Runtime. Recommended for most use cases due to portability and speed.
    *   **Sherpa-NCNN:** Optimized for mobile and embedded devices using the `ncnn` framework.
3.  **Supported Tasks:**
    *   Speech-to-Text (ASR) - Streaming and Non-streaming.
    *   Text-to-Speech (TTS).
    *   Speaker Identification/Verification.
    *   Voice Activity Detection (VAD).
    *   Keyword Spotting (KWS).
4.  **Local Processing:** All processing is done locally on the device, ensuring privacy and offline capability.
5.  **Multi-Language Support:** Extensive support for English, Chinese, and many other languages via pre-trained models hosted on HuggingFace and ModelScope.
